# Независимая техническая проверка macOS-порта LMZ Signal 2M 0.3.1

Дата: 26 октября 2026 года. Предмет проверки — исходный код порта, нативный транспорт обновлений, сборочный сценарий и независимые технические проверки. Подготовлен комплект исходников для запуска `bash tools/build_macos.sh` на Mac. В текущей среде Windows нет Xcode, macOS SDK и доступа к Mac. Нативный плагин, его подпись и ZIP для установки здесь не созданы и не объявлены проверенными.

## Идентичность и совместимость

Порт сохраняет версию `0.3.1`, видимое хосту имя `LMZ Signal 2M`, производителя `LMZ`, физический bundle `Signal2M.vst3` и идентификатор `sound.lmz.signal2m`. Коды производителя `Lmzz` и плагина `Sg2m` не меняются. В независимом macOS-хосте классы сравниваются как семантические Steinberg FUID; различие платформенного представления TUID не принимается за смену идентичности. Ожидаются прежние processor, controller и compatibility class.

`Tests/ReviewerMacVst3Checks.cpp` загружает реальный bundle через [CoreFoundation](https://developer.apple.com/documentation/corefoundation/cfbundle), читает его `Info.plist`, вызывает обязательные `bundleEntry`, `GetPluginFactory` и `bundleExit`. Редактор и DAW не открываются. После загрузки выполняются строгие сценарии независимого Windows-хоста: одиннадцать стабильных ID панели, автоматизация, MIDI-события с ненулевыми смещениями, нейтральная нота 60, баланс повторных нот, выбор последней удерживаемой ноты, работа MIDI-каналов, CC120/123, смена транспорта, моно/стерео, разные размеры блоков, конечное затухание, тридцатисекундная Oscillation, несколько экземпляров и сохранение состояния. Включено чтение настоящего 616-байтового состояния версии 0.1. Численные сценарии сверены с существующим независимым хостом без изменения их входных значений. Запуск этих проверок на macOS пока ожидается.

## Транспорт и время жизни

Источник macOS закреплён за таблицей `1ZyDHZskIvieqR_L6y4Ghu0gwvc6usByiNUF52y6AidM`, вкладкой `gid=640439888`, диапазоном A1:B1. Windows сохраняет `gid=0`. A1 задаёт версию, B1 — страницу перехода; транспорт не загружает B1 автоматически и не изменяет таблицу.

macOS использует фоновый `NSURLSession` с эфемерной конфигурацией. Cookies, кэш и хранилище пользовательских credentials отключены; HTTP-аутентификация и клиентские сертификаты отклоняются. Проверка сертификата и имени HTTPS-хоста передана стандартной проверке ОС, без обхода доверия. HTTPS-переход на HTTP запрещён, разрешены максимум три перенаправления. Тело ограничено 64 KiB независимо от Content-Length. Один абсолютный сетевой срок составляет восемь секунд; после него предусмотрена отдельная ограниченная попытка освобождения нативных ресурсов длительностью до 250 мс.

Проверены исходные механизмы владения: callback не удерживает `RequestControl`, стек вызывающего кода или владельца редактора. Делегат имеет только сырой указатель на heap-контекст. Его runtime-класс получает уникальное имя для загруженного образа и запроса, что устраняет коллизии Objective-C при загрузке нескольких копий плагина. Штатное освобождение требует invalidation, завершения callback, опустевшей последовательной очереди и освобождения нативных владельцев. При неопределённом teardown операция завершается ошибкой, образ защищается одной постоянной loader-ссылкой, а последующие запросы отклоняются. Такой аварийный путь намеренно сохраняет необходимое состояние до завершения процесса.

`ReviewerMacUpdateLifecycle.cpp` является отдельным загрузчиком без JUCE и кода плагина в основном executable. Он загружает минимальный тестовый dylib, проверяет реальные HTTP/header/body/TLS-сценарии, отмену, deadline, отсутствие временных pin и runtime-классов после штатного завершения, затем вызывает `dlclose`. Фактическая резидентность образа измеряется отдельно: успешный `dlclose` не называется доказательством unmapping. Последний сценарий через исключительно тестовый compile guard включает настоящий аварийный путь, проверяет единственную постоянную ссылку и отсутствие накопления контекстов при повторах. Удаление pin или сброс аварийного состояния тестам не предоставлены.

## Артефакты и имеющиеся результаты

Независимый `ReviewerMacPackageChecks.py` разбирает Mach-O напрямую по [структурам Apple](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/loader.h): две действительные 64-битные архитектуры arm64/x86_64, корректные границы fat/load-command структур, deployment target 11.0/10.15, системные Apple-зависимости и присутствие подписи. Он дополнительно проверяет plist, moduleinfo/FUID, платформенный endpoint, ZIP CRC, SHA-256, пути, права исполнения, manifest и точное совпадение файлов проверенного bundle с архивом. Криптографическая проверка подписи требует настоящего `codesign` на Mac; наличие signature command её не заменяет. Режим `--offline` явно оставляет нативную подпись ожидающей.

На Windows выполнены Python syntax-check и самостоятельная проверка парсера: четыре варианта fat-структуры и двенадцать отрицательных случаев, включая PE, одиночную архитектуру, усечение, чужую runtime-зависимость, неверный minimum OS и повреждённую подпись. Это результат проверки парсера, не результат сборки Mac. При ревью исправлены порядок создания checksum перед проверкой ZIP и разрыв между исходным протестированным executable и переподписанным доставляемым файлом: упаковщик сохраняет оба хеша и должен повторно запускать независимый VST3-хост на bundle, извлечённом из фактического ZIP.

Текущая полная Windows-сборка прошла; единственный полный регрессионный CTest завершился `8/8 PASS` за 27,91 с. Проверены DSP, MIDI, processor/state, updater, реальный Windows VST3 и самостоятельный Mac-парсер. Логи: `build/mac/windows-regression-build.txt` и `build/mac/windows-regression-ctest.txt`. Это подтверждение Windows-регрессии; установочный Windows-дистрибутив не перепакован. Проверка Objective-C++ с декларационными заглушками в Windows также проверяет только синтаксис и не подтверждает Apple SDK, линковку, availability API или поведение Foundation.

## Ожидаемое подтверждение

Обязательный следующий шаг — нативные сборка и все девять зарегистрированных CTest на Mac, затем проверка упакованного Universal bundle, подписи и извлечённого ZIP. Два slice в файле не подтверждают выполнение тестов на обеих архитектурах; отчёт должен назвать реально использованную архитектуру. Измерения Foundation teardown, динамического освобождения и TLS пока не получены. Необязательные внешние probes `--base`, `--tls`, `--untrusted-tls` не следует считать исполненными обычной командой CTest; отдельный опыт с недоверенным TLS-сертификатом не выполнен. Developer ID, notarization, визуальная проверка редактора, сканирование и воспроизведение в реальной DAW требуют отдельного фактического подтверждения. До получения этих данных статус поставки — исходники для нативной проверки, без утверждения «macOS PASS».
