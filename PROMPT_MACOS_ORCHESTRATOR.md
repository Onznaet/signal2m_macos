# LMZ Signal 2M — первое издание VST3 для macOS

Актуальный запрос пользователя от 26 октября 2026 года. Этот документ дополняет Windows-проект 0.3.1 и фиксирует задание оркестратору, исполнителям и независимому проверяющему. Это задание на реализацию и проверяемую поставку; подготовленные исходники сами по себе не являются готовым macOS-плагином.

## Результат

Перенести текущий **LMZ Signal 2M 0.3.1** на macOS. Первое Mac-издание имеет ту же версию 0.3.1, а не 1.0. Надпись BETA остаётся по существующему правилу major < 1. Требуется полный Universal VST3 bundle с двумя исполняемыми архитектурами **arm64** и **x86_64**. Целевой минимум — macOS 10.15 для Intel и macOS 11 для Apple Silicon; проверку этих минимумов нельзя подменять сборкой на более новой системе.

Имя в DAW — **LMZ Signal 2M**, физическая папка — **Signal2M.vst3**. Сохраняются Bundle ID `sound.lmz.signal2m`, производитель LMZ, коды `Lmzz` / `Sg2m`, семантические VST3 component/controller FUID, все 11 параметров, их IDs, диапазоны, порядок и формат состояния. Не включать номер версии или платформу в идентичность плагина.

Сохранить звук, MIDI-запуск и транспонирование, retrigger, краткое отпускание всего тракта, автоматизацию, графику, LMZ-карточку, ссылки, синие лампы и белую верхнюю лампу, крутилки, тумблеры и BETA из текущей программы. Иллюстрации в output/imagegen — рекламный арт, а не исходник интерфейса.

## Команда и владение файлами

Все назначаемые роли — `gpt-6.1-sol`, reasoning `max`, как задано пользователем. Оркестратор сохраняет архитектуру, согласует интерфейсы, разрешает технические разногласия и интегрирует работу. Не менять глобальные настройки Codex и не создавать пользовательские чаты.

- Исполнитель транспорта: новый `Source/UpdateHttpTransportMac.mm`, дополнительные узкие native-тесты. Windows WinHTTP не менять.
- Исполнитель сборки: CMake, Mac bootstrap/build/package, локальный workflow macOS, инструкции Mac. Не перепаковывать Windows-дистрибутив.
- Независимый проверяющий: отдельный технический CFBundle/VST3 host, независимая проверка Mach-O/ZIP/подписи, отрицательные fixtures и `REVIEW_MACOS_REPORT.md`. Не исправлять продуктовый код вместо исполнителей.
- Оркестратор: источник обновлений, переносимость общих updater-тестов, этот промпт, состояние разработки, интеграция и необходимые вопросы пользователю.

Работать в существующей папке проекта. Разделить владение до изменений. Число агентов определяет оркестратор в пределах фактического лимита среды. Файлы текста читать и записывать с явным UTF-8.

## Обновления macOS

Для Mac пользователь указал отдельный лист той же открытой Google-таблицы:

`https://docs.google.com/spreadsheets/d/1ZyDHZskIvieqR_L6y4Ghu0gwvc6usByiNUF52y6AidM/edit?gid=640439888#gid=640439888`

- macOS читает **gid 640439888**, Windows сохраняет **gid 0**.
- A1 — доступная версия, B1 — страница обновлений; сравнение числовых частей с дополнением нулями сохраняется.
- CSV endpoint Mac: `https://docs.google.com/spreadsheets/d/1ZyDHZskIvieqR_L6y4Ghu0gwvc6usByiNUF52y6AidM/export?format=csv&gid=640439888&range=A1%3AB1`.
- Таблицу не редактировать. Первое чтение при подготовке порта дало HTTP 200, `0.3.1,https://vk.ru/lmzvuk`; это наблюдение, не константа программы.
- Проверка автоматически один раз при первом Editor каждого Processor; повторное открытие использует кэш. Ручная кнопка повторяет проверку. Аудиопуть не обращается к сети.
- Состояния карточки, красная подпись «Новая версия» под логотипом и открытие общей карточки по ней сохраняются. B1 открывается браузером только по явному нажатию.
- Никакого автоматического скачивания, установки или учётной записи Google.

На macOS использовать нативный transport вместо заглушки, не подключать WinHTTP. Сохранить проверку TLS, общий сетевой deadline около 8 секунд, максимум 64 KiB, не более трёх redirect, отсутствие cookies/cache/auth/client-certificate и безопасную отмену. Не делать исключения ATS/TLS для публичного HTTPS-источника.

Отдельно доказать lifetime: никаких callbacks с raw-ссылками на завершённый request, Processor или stack; teardown не должен бесконечно ждать и не должен оставлять исполняемый код callbacks в выгруженном модуле. Для патологического асинхронного native teardown допустим документированный bounded cleanup и один fail-safe image pin на образ; недопустимы неконтролируемые потоки, бесконечные ожидания и накапливаемый pin на каждый запрос.

## Сборка и поставка

Закрепить JUCE 7.0.12 commit `4f43011b96eb0636104cb3e433894cda98243626`. Сохранить воспроизводимые совместимые правки JUCE, уже перечисленные в Windows bootstrap; не обновлять framework без необходимости. Mac bootstrap не должен скачивать Windows toolchain.

Подготовить одну воспроизводимую команду сборки на Mac с Apple Command Line Tools/Xcode и Python 3, либо локально описанный GitHub Actions workflow. Включить C++17 / Objective-C++ ARC только там, где требуется, правильные macOS frameworks и Universal architectures. Windows-цели сохранить работоспособными; Windows API в тестах оградить или переносить, а не выключать весь тестовый набор на Mac.

Mac ZIP должен содержать весь `Signal2M.vst3/Contents/MacOS/Signal2M`, Resources, Info.plist и подпись, а также инструкцию, заметки и необходимые оригинальные copyright/license notices. Не включать WinHTTP, NSIS, MinGW runtime или Windows DLL в Mac-поставку. Не помещать отдельный Mach-O файл вместо bundle. Сохранить исполняемые права и структуру пакета. Установка — пользователем в `~/Library/Audio/Plug-Ins/VST3` или `/Library/Audio/Plug-Ins/VST3`; автоматическую установку разработчиком не выполнять.

Для первого технического теста допустима локальная ad-hoc подпись: это не Developer ID и не нотарификация. Developer ID/нотаризация зависят от явно предоставленного владельцем способа подписи. Не искать и не публиковать секреты, не отключать Gatekeeper глобально и не выдавать ad-hoc за подтверждённого Apple разработчика. Изменения после подписи запрещены; перед ZIP проверить подпись и состав обеих Mach-O slices.

Публикация исходников, создание удалённого репозитория, отправка в облако, платные ресурсы и настройка аккаунтов требуют конкретного согласованного маршрута. Сначала подготовить локальные reviewable файлы. Не считать наличие gh на Windows доступом к рабочему macOS runner.

## Проверка и честность результата

Минимум: DSP/MIDI/параметры/state, все общие parser/version/startup/cancel/native HTTP tests, реальная загрузка Mac bundle через отдельный CFBundle/VST3 host без Editor, новые/старые state, stable FUID/11 IDs, независимость экземпляров и отсутствие нечислового звука. Universal bundle проверить на обе архитектуры; запуск одной native slice не подтверждает другую. Официальный VST3 validator, если доступен, дополняет технический host.

Независимо проверить fat Mach-O, load commands/deployment targets, исключение Windows-зависимостей, plist/модуль, signature, ZIP и SHA-256. Синтетические fixtures должны выявлять неверную архитектуру, неполный bundle, неверные IDs/версию, повреждённый архив и hash mismatch; они не заменяют native сборку.

Визуальную оценку и работу в пользовательской DAW на Mac выполняет друг пользователя. DAW самостоятельно не запускать. Формат этого задания — VST3.

На старте работ доступна Windows-среда, Mac/Apple SDK не подключены; друг пользователя имеет Mac для проверки, доступ для сборки пока не предоставлен. Если получить native среду пока невозможно, завершить независимые части, подготовить исходный комплект и точный способ native build, явно перечислить реально выполненные проверки и оставить native сборку/запуск ожидающими. Не переименовывать исходный ZIP в готовый plugin ZIP и не объявлять несуществующий бинарник готовым. Продолжить к native сборке после получения доступа или результата утверждённого запуска.
