# Технические решения Сигнал 2М 0.3

## Аудиомодель и MIDI

SynthEngine остаётся независимым от JUCE источником схемной модели. NoteVoice управляет его запуском от MIDI и монофоническим приоритетом последней удерживаемой ноты. Нота 60 нейтральна относительно VCO Freq; `noteSemitones = note - 60` добавляется к логарифму частоты. Скорость LFO и задержка не транспонируются. Итоговая частота ограничивается существующим безопасным диапазоном цифрового VCO, поэтому крайние настройки могут перестать давать точную октаву.

Каждый Note On заново запускает VCO/LFO, RC-цепи и память delay. При смене ноты примерно 3 мс переход начинается от последнего выходного отсчёта. Note Off последней удерживаемой ноты умножает весь результат на короткий release до 5 мс и затем останавливает модель. Это включает Oscillation: после окончания ноты бесконечного хвоста нет. VST3 сообщает конечный tail 5 мс. Новая нота всегда даёт новую симуляцию; mono fallback на более раннюю удерживаемую ноту тоже запускает её заново.

Список удерживаемых channel/key фиксирован и не выделяет память. Повторные Note On той же пары считаются и требуют соответствующих Note Off. CC123 снимает удержание канала, CC120 гасит его немедленно; другие каналы сохраняют свои ноты. Переход транспорта playing→stopped сбрасывает все ноты. Новый MIDI preview в остановленном хосте работает. Velocity0 трактуется как Note Off; прочая velocity не меняет уровень. Sustain, pitch bend и MPE не реализованы.

В PluginProcessor входной MidiBuffer разбивается по samplePosition. Между событиями NoteVoice обрабатывает соответствующий диапазон выходного буфера. Одновременные события сохраняют порядок хоста. Обрабатываются также события в нулевом callback. Поддерживаются только короткие MIDI-сообщения нужных типов, SysEx пропускается без выделения памяти. По окончании входной MIDI очищается, MIDI-выход не объявлен.

## Параметры и совместимость

Плагин сохраняет manufacturer/plugin code, имя Signal2M, Signal2MState и все 11 стабильных ID из 0.1. Автоматизация 7float/4bool и состояние привязаны к APVTS; значения атомарно читаются один раз на блок и сглаживаются ядром. Note pitch добавляется отдельно и не перезаписывает ручку VCO. Старые настройки загружаются, но звучание теперь требует нот согласно новой просьбе пользователя. Движущаяся история delay и удерживаемые ноты в state не входят.

NEEDS_MIDI_INPUT и acceptsMidi включены. JUCE 7 VST3 предоставляет служебные MIDI CC mapping параметры в дополнение к одиннадцати рабочим и стандартному Bypass. Они не являются новыми автоматизируемыми органами панели. Название Root Key и клавиатура Miscellaneous Channel Settings принадлежат FL Studio; плагин реагирует на транспонированные хостом note numbers. MIDI 60 выбран опорой; буквенное обозначение октавы различается между DAW.

## UI и показания LFO

Серебряная сердцевина, её асимметричный блик и machining trace рисуются с поворотом на угол ручки. Attachments и меню хоста сохранены. Статический фон содержит Power, DC, гнёзда и неподвижные части панели.

Аудиопоток публикует phase 0..1, выбранную LFO waveform −1..1 и active через lock-free atomics на Windows x64. Editor Timer 30 Hz читает только этот snapshot и обновляет изменившиеся области. В GUI нет собственного осциллятора или часов DSP. Верхняя яркость `0.5*(lfoValue+1)`; точка десятиламповой колонки идёт снизу вверх по `fract(phase+0.5)`. После окончания ноты индикаторы тёмные. Точная схема подсветки неизвестна; это выбранное простое приближение. На высоких LFO rate показания могут визуально алиаситься из-за частоты кадров.

## Стек, сборка и поставка

JUCE 7.0.12 commit 4f43011b96eb0636104cb3e433894cda98243626; LLVM-MinGW 20261020/Clang 23.1.4; CMake 3.31.6; Ninja wheel 1.11.1.3. Инструменты находятся в проекте. Два прежних патча JUCE для libc++23 воспроизводятся bootstrap.py; зависимостей нового типа в 0.2 нет. Плагин статически линкует C++runtime и использует системные Windows/UCRT импорты.

Выход: полный пакет `Signal2M.vst3`, ZIP `dist/Signal2M-v0.3-Windows-x64.zip` и обновлённое содержимое существующей папки `dist/Signal2M-v0.1-Windows-x64/`. Старое имя папки сохранено по просьбе пользователя копировать из прежнего места; её manifest и документы указывают 0.3. Упаковщик сверяет CRC/SHA-256 архива и каждой распакованной копии. Самостоятельно устанавливать в Common Files либо управлять FL Studio агентам не поручено.

Схемные приближения и модель обратной связи описаны в DSP_DECISIONS.md; фактически выполненные проверки — в REVIEW_REPORT.md. Совпадение с физическим прибором и визуальная приёмка не заявляются.

## Внешний вид0.3

Три SVG в assets встраиваются через juce_add_binary_data в Signal2MUiAssets, UiAssets.h, namespace BinaryData. Drawable загружается из встроенных данных; внешние файлы для запуска не требуются. Тумблеры выбирают один из двух векторов по существующему bool-параметру; семь ручек и звуковой тракт не изменяются. Исходные SVG и описание происхождения логотипа также включаются в artwork пользовательского ZIP.

Логотип трассируется вместе с надписями с пользовательской фотографии signal2m-right-panel.png. Надписи остаются path-контурами, системный шрифт не подставляется. Предельная точность соответствует исходному фото; оригинальный master SVG не предоставлен. Метод указан в assets/LOGO_SOURCE.md.

Верхний LED использует белую окраску, колонка — синюю. Несколько stops радиального градиента формируют мягкий ореол; timer dirty rectangles должны охватывать полный радиус свечения. Фаза и активность приходят из прежних DSP atomics, звуковое время в UI не создаётся.

Карточка LMZ — принадлежащий editor дочерний overlay над всеми контролами. Он затемняет весь editor и перехватывает ввод к underlying controls. Не используются блокирующий desktop modal loop или изменение аудиосостояния. Закрытие по свободному месту, backdrop, Close и Esc; ссылки обрабатывают собственный клик. Telegram URL предоставлен пользователем: https://t.me/lenmodzvuk. Две донатные ссылки пустые, их нельзя запускать как URL. Конфигурация label/url находится в Source/SupportLinks.h и не является параметром DAW. Переход в браузер происходит только после явного клика.

Публичная приёмка интерфейса и FL Studio остаётся пользователю. Отдельные SVG-ассеты можно проверять через растеризацию без запуска окна плагина. Техническая регрессия готового модуля проверяется тем же CLI VST3-host, что и 0.2.

## Ручной update checker и BETA, дополнение к 0.3

Версия CMake остаётся 0.3.0 по прямому указанию пользователя. Processor создаёт UpdateChecker с JucePlugin_VersionString; отдельная строка установленной версии в логике сравнения не задаётся. Владелец таблицы самостоятельно меняет удалённую версию; таблица агентом не редактируется. Метка BETA в статической панели условна по build major 0 и отсутствует начиная с 1.0.0.

Источник — публичный CSV export конкретного spreadsheet и gid=0 с ограничением range=A1:B1. Sheet metadata и read-only range подтвердили имя Distr и sheetId=0; anonymous HTTPS GET проверен отдельно. API keys, Google OAuth и пользовательская авторизация не нужны. B1 не загружается сетевым checker: он возвращает валидированный абсолютный http(s) URL для кнопки браузера.

Checker принадлежит Processor, но processBlock, prepare/reset и state не обращаются к нему. Конструктор не создаёт запросов или фоновых потоков. Только checkForUpdates из кнопки запускает один std::thread. UI опрашивает коротко защищённый mutex снимок результата из существующего Timer; callbacks в editor из worker не отправляются. Закрытие editor не отменяет и не ждёт запрос, повторное открытие показывает состояние того же экземпляра. Уничтожение Processor отменяет и завершает worker.

Windows transport использует async WinHTTP с одним steady_clock deadline 8 секунд на DNS/connect/headers/body и пределом 64 KiB. Перенаправлений не более 3, HTTPS downgrade, cookies и authentication отключены. Native callbacks владеют контекстом до полного session unload event, поэтому после завершения checker не остаётся выполняемого callback-кода в выгружаемой DLL. Отмена будит ожидания; handles закрываются worker-ом вне callback mutex. Условия ожидания, отмена и teardown проверяются контролируемым localhost server/DLL harness. WinHTTP — системная Windows библиотека, дополнительных runtime DLL в пакет не добавляется.

CSV валидируется как UTF-8 с поддержкой BOM/quotes/CRLF и ровно двух полей первой записи. Числовые части версий сравниваются лексикографически с нулевым дополнением: 0.1=0.1.0, 0.10>0.9. Неподдерживаемые/переполненные числа, неверный CSV/URL/HTTP/content-type/таймаут приводят к единому failed. При новой проверке старая ссылка удаляется. Строка результата рисуется простым текстом без markup. Проверка не скачивает и не устанавливает дистрибутив.


## Windows 0.4.0: музыкальное время и Post FX

Сохраняются исходные 11 параметров, их порядок, диапазоны и VST3 IDs. В конец
добавлены три bool: lfo_tempo_sync, delay_tempo_sync, fx_post. Заводские значения
нового экземпляра: false, true, true. Внутренние Parameters движка сохраняют
legacy-default false; Processor передаёт актуальные значения APVTS.
Отсутствующие поля при чтении старого state явно получают false, включая загрузку
в уже отредактированный экземпляр. Версия берётся из CMake 0.4.0, BETA сохранена.

TempoSync.h задаёт длительности в четвертных долях. LFO: 26 положений 8/1..1/512T;
Delay: 20 положений 1/1..1/512T. Внутри каждой пары straight/triplet, следующее
значение короче предыдущего. Исходные нормированные положения ручек сохраняются;
режим T меняет интерпретацию, не перезаписывая свободный параметр. LFO = BPM /
(60 * beats), delay_ms = 60000 * beats / BPM. Playhead читается только в processBlock;
нет BPM — последнее корректное, изначально120, положительные значения ограничены10..999.
Это tempo-rate sync с нотным retrigger, без phase lock к PPQ проекта.

При Post нотная огибающая находится перед сухой/параллельной FX-ветвью. Перезапуск
генератора отделён от полного reset: новая нота перезапускает VCO/LFO, сохраняя
delay/feedback. Note Off гасит источник за5ms, хвост продолжает обрабатываться.
Полный reset/transport-stop/All Sound Off очищают FX даже без активной ноты.
Для Post+Oscillation хост получает infinite tail; обычная обратная связь получает
консервативный конечный budget с защитой от переполнения sample count в JUCE7.
Максимальный sync delay24s при10BPM; память выделяется в prepare, не в аудиопотоке.
Свободные пределы остаются прежними, положение фильтра для длинных sync delay
ограничивается физическим диапазоном исходной модели.

Параметры и sound engine не зависят от таймера UI. T/T/P используют APVTS attachments,
включая host automation и восстановление. Аппаратный Sync остаётся LFO/VCO hard sync.
Готовые Mac0.3.1 артефакты не перепаковываются; текущая поставка только Windows.
